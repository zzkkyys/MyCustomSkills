# 匿名评审红线（触线可致该项目计 0 分）

填报须知原文：**"二、项目信息"中（"研究基础"除外）不得填写个人信息**，包括申请人姓名、设站单位名称、合作导师姓名等明显泄露申请人身份信息的内容；否则**评审专家可视为申请人故意泄露个人信息，计 0 分**（原文用词是"可视为……计 0 分"，是否触发由评审专家判定）。

尽管原文是"可视为"，后果——该项目评审直接归零——是全篇**代价最高**的：一处泄露即可能废掉整份申请，远重于任何文字瑕疵。因此**实务上一律按硬红线处理**，改稿时当作硬校验逐段过，不要拿"专家未必较真"去赌。

## 适用范围

- **必须匿名（栏目 1~5）**：选题依据、研究内容、研究方案、特色与创新之处、研究计划及预期成果。
- **可具名（唯一例外，栏目 6）**：研究基础。此处可写本人已发表工作、依托单位、合作导师、在研项目等——把需要"暴露身份的证据性内容"集中放这里。

## 高频泄露点（栏目 1~5 逐条排查）

1. **申请人姓名**：正文任何署名、"本人 XXX"。
2. **设站单位/依托单位名称**：如"哈尔滨工业大学""本校 X 实验室""我院"。改为中性表述或删去；确需交代平台条件时下沉到研究基础。
3. **合作导师姓名**：如"在导师 XXX 指导下""XXX 教授团队前期"。
4. **自引暴露身份**：引用本人已发表论文/专利时带出作者名、"我们前期工作 [作者, 年]"、"课题组已有"等。**默认做法：栏目 1~5 尽量不自引**，把作为个人基础的证据统一放到研究基础栏再具名。确有必要引自己的工作时，用**第三人称中性叙述**（"已有研究表明……"）且不点名——但要留意：即便去了名，**过于独特的方法、数据集、装置或小众前期结果本身也可能反推到人**，这类内容宁可改写抽象或下沉到研究基础，不要仅靠"改成第三人称"就当安全。
5. **项目/基金号**：本人主持的、可反查到人的项目编号、批准号。
6. **致谢/资助声明**：写明资助来源、单位平台名。
7. **图表水印/页眉页脚**：技术路线图、示意图里残留的单位 logo、姓名、文件名、模板页眉。
8. **可组合定位的独特信息**：极小众的设备型号、独家数据集、特定地点/工程名，组合起来足以锁定身份的，也算泄露风险，酌情脱敏。

## 自检清单（栏目 1~5 每栏跑一遍）

- [ ] 通读全栏，搜索本人姓名、导师姓名、单位名（含简称、别名、院系名）。
- [ ] 检查所有"本人/我/我们/本团队/本课题组/我校/我院/我室"等第一人称归属，改为中性或删除。
- [ ] 检查每一处文献引用/前期工作：是否点了自己的名、是否明示"这是作者本人的工作"。
- [ ] 检查数字标识：项目号、基金号、专利公告号是否可反查到人。
- [ ] 检查插图：有无 logo、姓名、单位水印、可定位的独特标注。
- [ ] 确认所有身份性证据已归拢到"研究基础"栏。

快速搜索辅助（把候选姓名/单位关键词替换进去）：

```bash
grep -nE '姓名|导师|本人|我校|我院|我室|课题组|哈尔滨工业大学|<你的姓名>|<导师姓名>|<单位关键词>' 01-选题依据.md 02-研究内容.md 03-研究方案.md 04-特色与创新之处.md 05-研究计划及预期成果.md
```

## AI 操作边界

处理稿件时也守这条线：不要为了"显得有基础"而在栏目 1~5 擅自补进单位、导师、本人成果的具名信息；拿不准某处是否泄露，标注出来让用户判断，不要默认保留。
