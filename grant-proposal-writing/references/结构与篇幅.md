# 结构、重心与篇幅

## 有固定章节要求时，一切以它为准

先确认**有没有规定死的章节/栏目结构**。很多基金、主管单位的申报书有硬性提纲（固定的一级栏目、必填小节、字数或页数分配）。**用户一旦提供，就原样落盘持久化**（写进计划文件或单独的 `章节要求.md`，逐字保留栏目名与顺序，不自行增删、改名、并栏），并以它为唯一结构依据——本文后面的通用骨架、页数分配、"合并某几章"等做法都**不适用**，只在没有固定要求、需要自拟结构时才用。有固定框架时，重心排布要在框架内实现：把主线内容放进更靠前、更充实的规定栏目，配角内容压进相应栏目，而不是改动栏目本身。

## 先问清主线，再排结构

排重心之前，必须先和用户确认**主线是什么**——这份申报书核心要做成的那件事、哪几项是主线、哪些是配角。不要自己替用户判断。主线定了，下面的重心排布才有依据：主线独立成条/成章并前置，配角整合收敛（在固定章节框架内则按上一节，在规定栏目内实现）。

## 重心失衡是最需要先解决的问题

申报书最容易出的结构病，是**某个容易写多的次要方面把主线淹没了**。凡是素材多、天然好展开的配套内容（如技术保障、风险防控、合规、平台建设之类），一不留神就占掉一半篇幅，而真正的主线（本课题要做成的那件事）反而被挤到角落。

**诊断方法**：列一张表，看研究内容各条、报告各章分别在讲什么、占多大比重。如果主线只在一两条里带过，而次要方面独占多条多章，就是失衡。

**对治**：
- 主线内容**独立成条/成章并前置**，扩为核心研究内容与独立章节，成为报告主体。
- 次要方面**整合收敛**：把原本分散在多条内容、多个章节的配套内容合并为一条内容、一章，保留必要厚度但压掉比重。
- 章节顺序体现主线：先讲主线（做什么、怎么做、成效如何），配套内容（保障、风险等）退到主线之后，最后验证/结论。
- 判断标准："这一段/这一章是在支撑主线，还是自己长成了另一条主线？"后者就要压。

> 参考：某次重构中把原本占三条研究内容、三个章节的配套内容压成一条内容、一章，同时把两块主线内容各扩为独立章节——重心即回到主线。此为示例，具体条目按本课题主线定。

## 篇幅控制在约定页数内（主体，不含附录）

评审对主体报告提纲常有页数预期（如约 30 页，以申报通知为准）。控制手法：

- **章节页数预分配**，写之前就定好。下表**仅适用于需要提交约 30 页主体报告提纲的场景**；若申报书用表格化模板、限字数栏目或基金申请书结构，按通知栏目重排，不套这张表。章名按本课题替换：
  | 章 | 内容 | 页数 |
  |---|---|---|
  | 一 | 绪论（背景、目的意义、概念界定、思路方法） | ~4 |
  | 二 | 研究进展与需求分析 | ~4 |
  | 三 | 〔主线的前置铺垫，如对象/需求分析〕 | ~4 |
  | 四 | 〔主线核心之一〕 | ~5 |
  | 五 | 〔主线核心之二〕 | ~4 |
  | 六 | 〔配套/保障，整合为一章〕 | ~4-5 |
  | 七 | 评测/实证/验证 | ~3 |
  | 八 | 结论与建议 | ~2 |
  | | 合计 | ~30 |
- **细节下沉到附录**：术语表、参考文献、指标/样本、各类对照表、流程图——都进附录，不计入正文页数。
- **消除重复**：免责与边界说明集中讲一次；同一套概念不要在多处逐字复述，第一次讲清、后文引用即可。

## 提防反向膨胀

去列表化、学术化的过程会**自然加长**文字（一句条目展开成一段论述）。同时 AI 润色倾向于：
- 把删掉的列表、表格、英文术语重新加回；
- 越改越长，堆叠修饰；
- 擅自新增数字、机构、方法、结论等事实。

每轮改完对比字数与页数，盯住这三点。逐段审阅时把"字数与原段相当、不得明显膨胀、不得加回已删内容、不得新增事实"写进约束（见 `审阅prompt.md`）。

## 不要写死不确定的信息 / 不要自我贬低

- 经费额度、周期月数等**未确认的数字不要写死**。用户确认前用"据实""按计划分阶段"等表述。
- 不写"短周期""小型""报告型研究"这类**自我贬低/自我设限**的限定，它们会削弱申报竞争力，且常显突兀。
